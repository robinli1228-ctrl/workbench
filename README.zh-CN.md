群聊 Agent 卡片新增临时“侧边聊天”（Claude / Codex），复用会话页的输入、附件和只读侧聊机制。引用选中的卡片，使用原会话当前上下文，不回写群聊或主会话。需要 Home 与 Worker 同时支持新能力；本分支尚未部署。

# Agent 协作工作台

一个自托管的项目群聊工作台，把你已有的 AI 编程 CLI 和订阅组织成协作团队。Codex、Claude Code、Grok Build、Antigravity 可以作为不同角色，在 Mac 或服务器执行；Home 保存记录、维护协作状态，Worker 驱动真实的原生 CLI。

> 开发预览版（`0.4.0`），面向单个可信操作者或小型可信团队。工作台不代理模型 API，也不替代 CLI 的原生指令、登录和工具。

项目文件同步新增可选的**简单元数据模式（两台设备）**，只用于目录范围，保留展示端必须是 Mac 的限制。两端 Worker 都须声明 `sourceSyncMetadataMode:1`；已有范围保持原来的内容哈希策略。新模式把每端的存在状态、纳秒修改时间和大小与该端上次确认的基线比较。普通观察不计算内容哈希；仅双方都变化时核对该路径，相同内容不用上传文件。元数据终态批次在 Worker 确认安全后回收专属暂存；恢复结果不确定时延后，重启后继续补清。冲突保留双方原件，由用户主动发起已有修复流程。修改时间和大小相同仍可能漏检内容变化。已有文件缺可信基线时保持待建立状态；显式首次初始化现已提供，30 天元数据同步记录现已提供。进程内 HTTP 集成属于开发证据，不等于真实 Mac/Linux 验收。详见[元数据模式契约](docs/design-source-sync.md#15-simple-metadata-mode-s1)。

原生会话重新发送消息或再次点击“引导”时，会先向 Worker 核对原进程状态（需要 `nativeTakeoverRefresh:1`）。确认空闲则复用，确认退出则释放旧占用；连接失败或进程身份不明时保留队列并明确报错。已点过引导的消息可以再次点击核对，只有请求提交期间禁用按钮。

会话、群聊和角色侧栏的说明收进标题旁的信息点，悬浮、点击或键盘聚焦可查看完整内容；不改变提示的来源和任务状态。

## 当前版本提供什么

- **角色协作。** 用户可以直接派任务，也可由主管协调；角色通过统一的 `wb` 入口咨询同伴、查询团队和历史、读取报告或请求用户确认。职能说明与可选的执行提示词分开，信息按需获取。
- **CLI 外部队列。** 可选 V3 会话在运行中的 CLI 外部合并消息，核实原生输入边界后才投递。保留原请求、等待和迟到回复；必要续接不重复扣传播预算。讨论正文仅通过 `wb note` / `wb chat post` 公开，原生流式和最终正文留在执行详情。
- **独立审核。** Workbench 的历史、衍生输入和受控文档读取，在明确解除隔离前持续保护。这不是操作系统沙箱，也不能删除原生会话已经见过的内容。
- **真实本机文件。** 资源和文档链接按仓库范围与相对路径读取绑定 Mac 的实际文件，不依赖同步开关。可选源码、文档和必要资源的保存后后台同步保留冲突双方版本，写入前重新核对；Git 提交、审核和合并另行负责。
- **可见的进度与界面。** 只读实时现场展示输入、输出和工具过程；页面状态只表示执行进度，审核结论留在正文与报告。提供额度重置详情、本机文件状态和紧凑附件预览；启用源码跟踪的执行单独记录输入前文件核验耗时，不混同 CLI／模型处理时间。基础设置 tab 吸顶，主管角色设置与项目设置分离。
- **会话安全恢复。** 设备并发限额、五分钟空闲复用、已核实残留进程回收，以及中断旧工作前的用户确认。停滞提醒默认开启，静默十分钟后检查，不扩大用户授权。有任务记录的群聊以 todo/in_progress 为准，全部完成或取消后不提醒；没有任务记录的群聊沿用消息规则。首次初始化从当前消息末尾开始，明确关闭的设置不变；已成功回复且无等待、未结束子请求或转交时不提醒。

协作会话广播已停用，项目开关关闭，不再产生新批次，已有记录仍可查看，仅保留用户明确释放已有评审意见和结束已有会话的入口。安装软件不会自动开启文件同步。启用或公开服务前，请阅读 [V3 实测验收](docs/design/session-queue-v3-acceptance.md)、[文件同步契约](docs/design-source-sync.md)、[CLI 占用恢复](docs/design-cli-session-recovery.md)和[限制与路线图](#限制与路线图)。

## 为什么做这个项目

基础设置中的“远程访问”用于管理可选的独立中转模块。在 Home 所在电脑，卡片显示状态、服务器地址和密码是否已设，旁边一个开关启停；服务器地址和密码在编辑弹窗里改，域名及特殊 SSH 参数收进高级设置，本机路径和密钥不显示。已有安装通过 Home 启动器的私有 `REMOTE_ACCESS_CONFIG` 指向原配置，否则使用 `DATA_DIR/remote-access/config.json`。中转保持独立进程，登录固定有效 15 天，公网登录不能修改本机中转设置。更换 IP 不会自动安装服务器，须先完成服务器部署。详见[模块说明](modules/remote-access/README.md)和[接入设计](docs/design-remote-access-settings.md)。

项目源于一个很实际的场景：一个人，多个 AI 订阅（不同厂商、不同模型），以及多台机器。

- **不同模型互相审核、互相补充。** 一个模型写代码，另一个从不同角度审核，第三个负责规划或测试。每一个都是一个*角色*，拥有各自的 CLI、模型和提示词。对固定 Git 提交做独立审核是一等公民级别的工作流。
- **用好你已经付费的额度。** 大多数账号在周期结束时都有用不完的 token。角色本质上就是“这个 CLI + 这个模型 + 这台机器”，所以你可以决定工作如何分摊到各个账号，并随时通过编辑角色调整分配。角色旁会显示 token 统计，以及 CLI 提供时的剩余额度，方便你有针对性地调整分配。
- **多台服务器和设备协同工作。** *Home* 节点保存项目状态，任意数量的 *Worker* 节点（你的笔记本、Linux 服务器、云主机）连接到它，运行各自机器上安装的 CLI。代码以固定的 Git 提交在设备间流转，文件以附件形式传递，主管角色可以协调分布在不同机器上的角色。

工作台不会取代这些 CLI，也不代理模型 API。它驱动你已经安装并登录好的 CLI，自身不保存任何厂商凭据。

## 语言

设置默认打开「基础设置」，页签依次为：基础设置（Home 状态、远程访问、语言、浏览器 API Token）、设备与 CLI、代码托管账号、提示词与模板（平台提示词、主管提示词、角色模板、后台整理）、数据、关于（版本、检查更新、配置指南）。Home 访问令牌验证后保存在此浏览器，关闭再打开会自动使用，需要时可在基础设置里修改。请使用可信浏览器；清除网站数据、使用无痕模式或更换浏览器、访问地址后可能需要重新设置。语言选项切换界面及展示的默认文本，与实际模型输入的语言分开。本 README 与[操作指南](docs/OPERATING-GUIDE.zh-CN.md)也提供简体中文版本。

派工附件的已知 JSON 封装在群聊卡片和全文弹窗中展开为 Markdown，标题、列表和代码正常排版；普通代码转义、保存原文和复制内容保持不变。

角色收到协助结果后继续派工时，引用实际触发续接的公开反馈，原始用户任务来源保留；旧记录只在读取时纠正引用，不改历史正文。无法确认或受保护的反馈不猜测引用。

运行详情复用会话页的活动块：工具和运行提示统一折叠，重复思考提示合并计数，不再逐条显示嵌套CLI日志卡；错误保留可见。

会话列表先显示 Home 已保存的目录，再由 Worker 核验；切换页面保留已知条目。历史摘要按文件变化失效，不再固定20秒过期；未变化的列表刷新不重复读取正文，失败读取仍可重试。

页面中的中文正文转为简体展示，包括聊天消息、引用、全屏回复、执行输出和 Markdown 预览；仅作繁简字形转换，不翻译英文，也不增加模型调用。代码、命令、路径、编辑中的输入、原文窗口、复制内容及保存记录保持原样。

聊天正文保持现有高度，内容较多时可在框内滚动，不再超过十行就截断。状态刷新保留每条消息的阅读位置；长文仍可点击原有全屏按钮查看。

通过 Workbench 对话执行的 Codex、Claude Code、Grok、Antigravity，使用英文的平台维护执行模板，并将自然语言正文的发送副本转为繁体。聊天记录和自定义提示词的保存原文不变，不自动将自定义提示词翻译成英文；代码、命令、路径、标识符和精确引用文本保持原样。后续对话及配置更新也采用同一策略，不增加模型调用。此功能不改写原生历史、附件、工具结果或 SSH 终端直接输入，需要各执行设备升级到此 Worker 版本。

任务启动时，Worker 分别记录实际执行仓库的目录、完整 HEAD、未提交状态，以及当前项目绑定目录的对照 HEAD。旧会话保留原目录；旧副本缺失或身份不符时，不静默改用较新的项目副本。结构化固定版本不一致会在模型输入前阻止本次启动，不自动拉取或切目录，也不修改其他任务。已获准写入阶段的续接可保留已验证的提交结果。执行详情显示实际输入版本；这些是启动时检查，不增加后台轮询或远端 fetch。

精简输入仍传递简短的阶段边界和必要报告入口。独立审核只读：仍有必须修改的问题用 `failed`，无法核实用 `blocked`，需要用户决定用 `needs_input`，只有非阻塞建议可以随 `passed` 交回。默认规范补充材料路径与哈希、编号修改处理结果和阻塞负责人。只有精确匹配的旧内置默认提示词会升级；自定义、明确留空、正在执行回合的配置快照和历史报告保持原样。

## 主要功能

左侧可切换「群聊 / 会话」，两种模式沿用三栏布局。「会话」默认展示全部会话和全部 Agent，合并带标题的新建会话、独立原生历史及群聊会话。紧凑的设备／来源与 Agent 下拉筛选可分别查看这些记录；操作后和从 iTerm 返回时自动刷新，不删除历史。中间默认只读，确认接管及执行权限后可在页面继续聊天、上传附件、查看实时过程、停止当前轮次和结束接管；也可从右侧进入 iTerm。Codex、Claude、Agy 在支持的模式下保留驻留进程，Grok 按轮恢复。新建终端会话的权限绕过选项仍默认不勾选；页面接管不注入 Workbench 角色提示词。Agy 二进制历史暂只显示元信息。目录读取需要能力 2，安全页面接管需要 `nativeTurns:3`；原生编号关联及验收边界见[原生会话浏览设计](docs/design-native-session-browser.md)。

会话页左侧同一项目、群聊、角色只保留最新会话入口，不再展开历史子菜单。在右侧聊天区向上滚动，按页读取更早消息，再接上同一角色的旧会话，并按日期、设备和原生会话标识分隔。历史读取不切换发送、接管或归还目标，也不删除或合并原始记录。分页要求 Worker 支持 `nativeHistoryPages:1`；旧版本会明确提示升级。读取量和响应大小受限，超大单条记录或不支持的二进制历史会提示无法预览，原文件仍保留。

角色的终端弹窗直接展示最近的历史会话，不使用下拉框，也不删除旧记录。「打开新会话」复用独立新建窗口，预填角色的设备和 CLI，文件夹单独选择，不带入群聊历史或角色提示词。「核对并恢复历史会话」保留原有精确会话核对及终端归还操作。

执行详情在「产物」之后增加「结果原文」标签，替代执行结果的独立原文按钮和弹窗。按需读取选中 Run 的原始文本，支持分段加载和原样复制全文；普通消息的原文和引用仍对应消息自身。

角色卡片的模型名称后新增无数字的小型上下文占比圆环，与账号剩余额度分开。Claude 使用最近一次主请求输入和原生模型上限，Codex 使用最近请求输入及上报的窗口；悬浮或点击查看占比、token 数和采集时间。上限未知、CLI 未提供可靠数据或升级前历史未采集时，显示未知，不猜百分比。只被动采集，不调用模型，不自动压缩。

Claude、Codex 的额度从正常群聊和会话的执行连接被动接收，不再额外调用 Claude `/usage` 或 Codex `account/rateLimits/read`。安装、登录和模型发现检查保留；Grok、Agy 的原有额度查询不变。后台保留真实采样时间，每个窗口到自己的重置时间变为未知，超过三小时没有新样本标为非最新（额度弹窗显示多久前更新）；Worker 重启或一次超时的登录检查都不会丢掉额度；不猜测满额，不借用其他账号的数据。沿用现有旧额度提示。该改动不读取外部终端、不修改认证凭据或历史，也不表示原生认证续期或登录失效问题已经解决。

项目设置按「基本信息」「仓库与工作区」「文件同步」「协作与调度」四个顶部固定标签分类，切换保留未保存的输入，各区块仍分别保存并就近显示结果。项目文件同步可从项目设置和资源列表进入。点击主管卡片打开独立的角色详情弹窗，采用与其他角色相同的设置／历史记录标签和布局；项目配置仍放在项目设置中。

应用内弹窗统一采用白底小圆角、灰色无框关闭图标和蓝色主按钮。角色设置／历史记录直接放在标题栏，切换保留未保存输入；长表单滚动时保留可见操作栏。浏览器原生确认框与系统文件弹窗保持原有行为。

设置页和项目设置是灰底上的一列白色卡片：卡片标题带一行说明和图标操作，每行是名称、值或状态标签、行内操作，修改在弹窗里进行。设备与 CLI 每台设备一张卡片；Token 统计、定时任务和文件同步仍是一张白底卡片。设置分类标签直接放进固定标题栏，窄屏可横向滚动标签。项目仓库按仓库地址自动选用代码托管账号（仓库所属空间的账号 → 默认账号 → 该平台唯一账号），只有新建仓库时才选择创建在哪个账号下。会话更保守：只有 HTTPS 远程地址属于某个账号自己的空间时才用该账号，SSH 地址继续用设备自己的密钥。仍保留完整页面布局、原有保存入口和统计内容；视觉调整不改变采集、派发或后端行为。

以下各项均已存在于当前代码中。仅有设计的内容单独列在[限制与路线图](#限制与路线图)中。

**协作**

- 项目群聊，通过 `@角色` 派发任务。显式 @ 多位角色时分别为每位建立任务，最多四位，不自动转交主管。回复默认 @ 被引用的 Agent，手动 @ 优先；回复用户消息只引用，不凭空派工。忙碌角色继续按原队列等待。普通 Agent 消息不隐式派工；旧会话广播不再创建讨论批次。
- 每个项目拥有自己的角色，每个角色有独立的设备、CLI、模型、推理强度和 Markdown 提示词。原八个模板保留空执行提示词；可选的跨设备协同、本地开发和本地测试模板带有执行提示词。可在“设置 → 平台提示词 → 角色模板”中新增、修改、删除或恢复模板，仅影响之后新建的角色，不自动创建项目角色。
- 同设备 Codex/Grok 的 CLI 变更走“交接并切换”：保留角色和历史，等待已接任务完成，由新原生会话核对交接，确认进程退出后才保存配置。提交前取消保留原绑定。需要兼容 Worker；其他 CLI 尚未验收，会明确拒绝切换。当前验收状态见 [CLI 切换设计](docs/design-role-cli-switch.md)。
- 每个项目有一个固定的*主管*：接收不带 `@` 且未引用消息的新请求，提出仓库/角色配置卡（确认后才会生效），使用 `wb task` 记录工作、`wb call` 派工或转交。旧 schedule、collaboration、pass 命令已删除；已有计划仍可收尾并保留只读历史。主管卡片固定显示在普通角色上方，点击打开角色详情中的设备、CLI、模型和思考深度配置。
- 通过统一的 `wb` 命令向所有受管 CLI 提供结构化的角色间工具：咨询其他角色（`wb call` / `wb wait`）、报告业务结论（`wb report`）、撰写交接记录（`wb handoff`）、请求 Git 交付（`wb deliver`）。模型输出里的 `@` 不会派发任何工作。
- 一次 `wb call` 可以发给一个或多个角色：同一正文重复 `--role` 指定接收人，只展示一条指令，各自保留请求和回复；相同编号重试不重复派单。指令成功登记后自身显示已完成，接收方执行进度放在各自回复上。卡片上方显示引用和接收人，底部左侧显示类型与状态，右侧显示操作按钮。
- 排队、按角色和按节点的并发限制、取消、对排队中的人工消息“立即引导”，以及需要 Worker 确认的显式停止。
- 原生会话续接：每个角色在多轮之间保留其厂商会话，并由后台对话整理器维护共享的项目摘要。
- 可选、默认关闭：同行讨论预览（`WB_DISCUSSION_PREVIEW`）。

**多设备**

- 功能分支已接入 Q/F 只读工具 `wb read source|query|file <JSON>`，定位注册来源并读取刚保存的实际内容，不等待同步、不检查 Git clean、不创建执行副本。项目默认关闭，由认证的 `read-access` API 显式授权设备、范围和两个固定查询。相同请求 ID 重放原观察，新 ID 才读取新事实；回包与持久结果都有上限。缓存补齐、目录落盘及 S 快跑尚未实现。验证与发布状态见 [P1 计划](docs/plan-cross-device-execution-p1.md)。
- 通过经过认证的 WebSocket 实现 Home/Worker 分离。Worker 主动向外连接；Home 不会主动访问任何机器。
- 可靠投递：持久化的命令与事件发件箱、幂等的命令 ID、重连后对账，对状态未知的执行不会自动重跑。
- 每台设备有各自的项目目录，每个仓库有一条长期的项目基线分支（Git worktree），并支持基于固定 SHA 的跨设备交付，推送前必须经过明确确认。
- 附件（图片和文件，每条消息最多 6 个，每个最大 20 MB），带 SHA-256 校验，并提供“发送到设备”操作，用于把文件传给另一台已绑定的设备。
- 通过 SSH 的设备接入助手（在远程 Linux 机器上安装并连接 Worker），以及可选的由 Home 管理的反向 SSH 隧道。
- macOS Home 的远程桌面入口：检查已登记服务器的 xrdp，建立本机回环 SSH 转发或复用核对一致的现有同用户转发，然后打开 Windows App 的已保存连接。未知或有歧义的监听仍会阻断；入口不会终止外部管理的隧道。启动客户端不代表桌面已登录。
- 终端接管：在 iTerm 中继续已结束的原生会话（macOS 入口；远程设备通过你自己的 SSH 配置访问），期间平台会暂停向该设备派发。

**运维**

- 定时任务（单次、间隔、每日、每周），以及不调用模型的进度巡检，仅在出现新异常时唤醒主管（`wb timer`）。
- 按设备统计 token 用量，由 `ccusage` 采集；每日柱状图按模型堆叠，合并所选设备上同一模型的用量。
- 保存 GitHub 和 Gitee 账号，并可选地创建仓库（默认私有）。
- 可安装的 PWA 外壳，桌面三栏布局和手机抽屉布局。
- 状态读取超过 20 秒会超时并自动恢复，不重发任务。回到页面或网络恢复时刷新状态，保留未发送草稿；连接详情显示最近成功更新时间。
- 静态文本与状态、聊天读取按浏览器支持协商 gzip，减少 SSH 传输量；流式事件与附件保持原样。页面小图标使用已有的 192px 图片，离线壳安装不再提前下载可选的大尺寸图片。

## 架构概览

```
 浏览器 (PWA)  <--HTTP/SSE-->  Home  <--认证的 WebSocket-->  Worker A  --> codex / claude / grok / agy
                                |                            Worker B  --> codex / claude / grok / agy
                         SQLite（项目、角色、                ...
                         房间、运行、队列）
```

- **Home**（`src/home.mjs`）：Web UI 与 REST API、SSE 更新、项目状态的唯一来源、调度器，以及 Worker 的 WebSocket 端点。基于 Node 的 HTTP 服务器和内置 SQLite 构建。
- **Worker**（`src/worker.mjs`）：每台机器一个。探测本地 CLI，在项目工作区中运行它们，维护本地数据库和发件箱，并把事件回报给 Home。
- **运行时适配器**：Codex 通过 App Server 协议；Claude Code、Grok Build 和 Antigravity 通过它们的非交互 print/stream 模式。
- **`wb`**（`bin/wb`）：所有受管 CLI 用来回连工作台的工具。它通过每轮独立的文件桥与 Worker 通信，因此 CLI 沙箱不需要网络访问。
- **Web UI**（`public/`）：纯 ES 模块，无需构建步骤。

细节与接口边界见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)（英文）。产品范围见 [docs/PRD.md](docs/PRD.md)（英文）。

```sh
nvm use          # 可选，使用 .nvmrc 中的版本
npm install      # 或：npm ci
npm run dev      # 以两个独立进程启动 Home 和 Worker
```

打开 <http://127.0.0.1:4317>。默认只监听本机回环地址。

然后在界面中：

1. 打开“设置 → 设备与 CLI”，检查你的设备及其 CLI 是否已被检测到。
2. 创建项目。选择在线设备、已登录的 CLI 和模型作为项目主管，并为项目填写文件夹名。

```sh
npm start        # Home

```

### 项目记忆：`AGENTS.md`

每个受管项目只在项目根目录保留一个权威记忆文件 `AGENTS.md`。Workbench 创建项目文件夹或关联已有 Git 仓库时，仅在文件不存在时生成 `AGENTS.md` 模板（项目目标、规则和约定、构建和测试命令、关键决策；只写结论，约 200 行以内）和一行内容为 `@AGENTS.md` 的 `CLAUDE.md`。已有文件绝不覆盖。在 Git 仓库根目录中，只把新建的这两个文件在本地提交（`chore: add AGENTS.md project memory`），不暂存其他内容，也不推送。提交失败（例如未配置 Git 身份或被 hook 拒绝）时，文件保留为未提交状态并报告错误。Codex、Grok 和 Agy 原生读取 `AGENTS.md`；Claude Code 需要 2.1.281 及以上版本才支持 `AGENTS.md`，而 `CLAUDE.md` 指针覆盖了它的默认模式（只要存在 `CLAUDE.md` 就不读 `AGENTS.md`）。规则或关键决策变化时，任何角色都可以更新 `AGENTS.md`；保持简洁、只写结论，并提交修改。`AGENTS.md` 管规则和偏好。此外 Workbench 在 Home 上保存一份全平台共用的平台记忆：环境、账号与密钥、教训和解决办法、固定流程、个人信息、全平台的决定等跨项目有用的内容，所有项目、角色、CLI 和设备共用；只跟某个项目有关的决定和进度不记，用 `wb history search` 查该项目的聊天记录。它由单独配置的记忆整理模型（设置 → 记忆）每天从各项目的群聊消息里整理，每个群聊记录整理到哪条消息，失败的批次稍后重试；整理时会读项目的 `AGENTS.md`，已经写在里面的不重复记；偏好和只属于某个项目的规则不进记忆，由角色自己写进 `AGENTS.md`。整理模型每天还会检查一遍重复和冲突：重复的合并，冲突的以新的为准；整理用的 CLI 会话结束后即删除。记忆不注入提示词，群聊角色和会话页的 CLI 需要时都用 `wb memory search` 查；设置 → 记忆 里可以分页查看、筛选、添加、编辑和删除，人工保存的条目在事实变化时由整理原地改写，不会另外复制一条。旧的 `.workbench/MEMORY.md` / `INDEX.md` 不再使用（磁盘上的旧文件不会被删除）。过程历史用 `wb history search` 查询。

## 配置

角色编辑区将**角色职能**（供其他角色选择协作对象）与**角色提示词**（本角色执行时注入）分开。本角色不会从团队目录收到自己的职能。设备离线时仍可只修改文字，保留 CLI 和模型绑定。已有自定义提示词不被自动覆盖，未填职能表示未指定，不按名字猜测。

所有配置都通过环境变量完成。可参考 [`.env.example`](.env.example)；应用本身不会加载 `.env` 文件，请在 shell 或服务管理器中导出这些变量。下表中的值均为占位符。

**Home**

| 变量 | 默认值 / 用途 |
| --- | --- |
| `PORT` | `4317` |
| `HOST` | `127.0.0.1`。非回环地址必须设置 `API_TOKEN`，并且应放在 HTTPS 反向代理之后 |
| `DATA_DIR` | 项目内的 `.data/home` |
| `API_TOKEN` | 浏览器访问令牌，监听非回环地址时必填（例如 `xxxxx`） |
| `WORKER_TOKEN` | Worker 共用的注册令牌。未设置时会生成到 `.data/home/worker-token` |
| `TOKEN_USAGE_TIMEZONE` | token 统计的日界线时区，默认使用系统时区；可设置以覆盖 |

**Worker**

| 变量 | 默认值 / 用途 |
| --- | --- |
| `HOME_URL` | `ws://127.0.0.1:4317/worker`；远程 Home 使用 `wss://xxxxx/worker` |
| `WORKER_TOKEN` | 必须与 Home 的令牌一致（例如 `xxxxx`）。本机会从 Home 数据目录读取 |
| `WORKER_ROOTS` | 允许的项目根目录，以操作系统的路径分隔符分隔（例如 `xxxxx`）。默认为项目目录 |
| `WORKER_DATA_DIR` | `.data/worker`；每个 Worker 一个目录，绝不可被两个进程共用 |
| `WORKER_CONCURRENCY` | `2` |
| `NODE_NAME` | 显示名称；默认为主机名 |
| `NODE_KIND` | `local` 或 `cloud`；Linux 上默认为 `cloud`，其他系统默认为 `local` |
| `CODEX_BIN`, `CLAUDE_BIN`, `GROK_BIN`, `AGY_BIN` | CLI 可执行文件；当 `PATH` 不同时请设置绝对路径（`xxxxx`） |
| `CLAUDE_MODEL_ID` | 当 `CLAUDE_BIN` 指向兼容 Anthropic 的启动器时，对外声明的模型 ID |
| `CLAUDE_CONFIG_DIR` | 原生会话目录；当包装器改变了 `HOME` 时需要设置 |
| `NODE_ID`, `WORKSPACE_ROOT`, `REMOTE_DESKTOP_URL`, `CCUSAGE_BIN` | 可选覆盖项，见 `src/worker.mjs` 和 `src/token-usage.mjs` |

可选功能：`WB_DISCUSSION_PREVIEW=1` 配合 `WB_DISCUSSION_VALIDATED_CONFIGS`（由你已验证过的 `{runtime, model, version, bin}` 条目组成的 JSON 数组）可启用同行讨论预览。

### Home 与远程 Worker

在一台常开的机器上运行 Home，并从其他机器连接 Worker。对于少量个人节点，使用 SSH 隧道即可：

```sh
# 在 Worker 机器上
ssh -NT -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -L 14317:127.0.0.1:4317 xxxxx@xxxxx
```

```sh
# 在 Worker 机器上的另一个终端中
export HOME_URL=ws://127.0.0.1:14317/worker
export NODE_NAME=xxxxx
export WORKER_ROOTS=xxxxx
read -r -s WORKER_TOKEN && export WORKER_TOKEN   # 粘贴 Home 的 Worker 令牌
npm run worker
```

如果你已有 HTTPS/WSS 反向代理，设置 `HOME_URL=wss://xxxxx/worker` 并跳过隧道即可。Node 本身不终止 TLS。更多部署方式见 [docs/OPERATING-GUIDE.zh-CN.md](docs/OPERATING-GUIDE.zh-CN.md)。

## 限制与路线图

在依赖本项目之前，请先了解以下事项：

- **仅限可信操作者。** 所有浏览器共用同一个 Home 凭据；没有按用户区分的身份和权限，不能按设备撤销凭据，Node 内部也没有 TLS。Worker 注册令牌是一个共享密钥。
- **自动批准执行。** Codex 以 `workspace-write` 和审批策略 `never` 运行；Claude Code、Grok Build 和 Antigravity 在 Worker 指定的工作区内使用跳过权限确认的参数运行。没有原生的逐步审批。`wb` 工具的允许列表并不是针对同一账号下恶意 shell 的沙箱。
- **单一 Home。** 没有复制或自动故障转移；运行在笔记本上的 Home 在笔记本休眠时无法派发任务。
- **跨设备会话交接目前只是设计，还不是功能。** 目前你可以把角色重新绑定到另一台设备、交付固定的 Git 提交、发送附件，但厂商的原生会话不会迁移。见 [docs/design-session-handoff.md](docs/design-session-handoff.md)。
- **尚未实现：** 其他 ACP 运行时、更多聊天通道（飞书）、多用户身份、Home 的人工主备切换、已交付分支的自动合并。
- token 统计反映的是 `ccusage` 看到的本地 CLI 历史，不是厂商账单。额度显示是对每个 CLI 的尽力探测，当 CLI 不提供时会显示“不可用”。
- 进程成功退出只代表一次执行结束，不代表工作已被验收。

项目状态和计划中的工作在 issue 跟踪器中记录。

### 群聊任务记录

`wb task list`、`show T3`、`create '<JSON>'` 和 `update T3 '<JSON>'` 管理仅存于 Home 的当前群聊任务列表。创建需要稳定的 `requestId`，更新需要当前 `revision`。这些记录不会自动派活或打断正在执行的角色。字段限制和计划结构见 `wb help`。

任务列表标题右侧默认勾选“只显示未完成”，不再展示手动新建任务加号。详情分为基础信息、任务步骤、修改历史三个 tab，默认打开任务步骤；步骤默认折叠，可新增、编辑和删除；每步只有一段必填“步骤说明”，不再单独填写步骤标题。卡片顶行展示说明摘要和可修改的状态；展开显示完整说明，点击协作与审核汇总行可调整配置。修改历史默认展开，可逐条收起；切换 tab 保留草稿，沿用原保存和版本冲突检查。

`wb call --task T3` 将显式派单关联到任务。普通派单保留负责人；`--kind transfer` 在同一事务中将负责人改为接收方，并设为 `in_progress`。负责人必须先在本轮用 `wb task update` 整段重写说明。关联派单及其续接收到当前任务说明和计划；若说明在该角色上次收到后改变，下一轮会标注。任务列表页面卡片已包含；这些计划记录与实际执行任务保持区分。

审核交付支持仓库子集：`wb deliver 编号 auto 说明 --review --repo KEY`（可重复 `--repo`）。未指定仓库的审核 SHA 必须仅存在于一个本地仓库。普通交付仍须包含全部仓库。只发布、绑定并以 detached 审核工作树接收所选仓库；未选仓库的未提交修改不阻塞审核交付。交付卡片列出仓库 key 并标注部分交付。
已取消的 wb report/schedule/collaboration/pass 会在读取本轮上下文前给出替代说明，并保持非零退出。结果通过最终回复交回；步骤依赖写在 wb task 计划里，wb timer 只用于时间提醒。提示词设置和角色编辑器按行标出旧命令。平台与主管提示可由用户明确点击更新为新默认，沿原保存接口校验 promptsRevision；不自动覆盖自定义文字。执行时只给含旧命令的自定义文字附短提醒。反向调用正在等待当前依赖链结果的上游时，提示直接写最终回复；其他角色循环仍拒绝。

简单模式初始化提供待建基线路径的分页预览，以及需要明确二次确认的两种操作：一次性核验内容，或使用选定设备覆盖初始化。覆盖前先保存双方版本，保存失败不写工作文件。操作复用有上限的现有批次，中断后可继续。元数据冲突副本只在两端回执、专属暂存清理和引用检查完成后删除；旧模式清单／版本和未解决冲突仍引用的字节保留。不复用旧哈希模式证据推断当前元数据基线，也不会自动迁移真实项目。

简单模式初始化续做须再次确认，并携带当前配置 revision 和稳定 requestId；相同请求重试不重复续做。仍被引用的副本每小时重查，重启保留退避时间；metadata 历史仅作审计，不阻止副本清理，旧模式历史仍保护字节。同路径新冲突继续持有旧版本未释放副本的清理归属。

项目同步设置的“同步记录”按游标每页 50 条展示实际文件尝试，可按精确相对路径、任一端设备、Home 记录时间和状态筛选。详情包含前后属性、重试链、冲突入口；未实际核验的哈希显示“未计算”。已有 Home tick 每天至少一次、每批 100 行清理到期审计；未结束记录从最后真实阶段变化起保留 30 天。未结束的操作恢复身份、基线、未解决冲突受到保护。终态恢复身份超过 30 天且批次和命令已结束后，按索引每批最多回收 100 条，仅删除仍指向它们的最新身份指针；显式删除项目也会删除审计和初始化记录。初始化任务也改为每页 50 条。浏览器交互和真实设备验收仍需单独执行。
